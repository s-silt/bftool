# bftool 安全修复候选说明

本修复基于源包标识 88b6e9cbdb2fc623d42e83d12314d9538b934856，整合已验证的恢复核心及八页 GUI 修复。该源包提交未出现在可获取的远端历史中，整合以当前 main 为父提交，保留远端文件与历史。源码合入不等于创建新 Release、部署或更新用户安装。

## 行为变化

- 计划携带规范源根、实际源路径及完整相对身份；执行再次核对源身份。同名不同子目录独立分配目的名称。
- 单文件与目录使用一致的相对清单语义。公开计划执行入口也执行 HashPolicy，dry-run 不恢复事务或写入索引。
- 增量成功记录绑定已验证的文件路径和内容快照，并核对实际历史副本。缺旧 hash、缺副本、源改名或改内容时不再把当前源状态认证为“已经备份”。规划不 seed/flush 索引，旧预览中的未变项在执行时重新检查。
- 新的阶段化事务日志保留源身份、目标及已验证快照。恢复必须补齐真实提交状态，不能把 retain_source 的“源仍存在”当成已移源。旧版本缺乏充分证据的事务保留并要求人工核对。
- 无所有权证据的部分目标不继续覆盖，另选唯一新目标完整重拷，原部分目标保留。已有校验清单同样保留；晚到的占用拒绝覆盖。
- 目的目录句柄贯穿复制与校验；异常链接、路径替换和未知占用保守失败。校验失败不再移动未知额外文件到隔离区，源与目标证据保留。移源使用 no-replace；异常初始化标记目录不递归删除。
- 整盘、单项目和单文件复查核对索引、项目树与清单。缺失/损坏/不可验证不能被汇报为“完好”；空新盘不产生已验证有数据的绿色记录。
- 真实复制/校验失败进入 failed 汇总，CLI 能返回非零状态。暂态跳过、取消和封盘仍按其独立语义处理。

## 架构边界

service 负责操作入口与策略；pipeline 编排预检、计划、执行和提交；archive 内分开源身份、复制、清单、catalog、增量和恢复。Channel 仅提供介质事实，不再宣称支持一个实际不可用、且缺少完整安全上下文的初始化写接口。初始化写入仍由完整 service/pipeline 路径负责。

计划经 LocalDrivePool/Channel 选择目标，H5 单可写判断使用一次扫描事实及类型化拒绝，不再依赖错误字符串匹配。DriveInfo 仍作为兼容边界存在，未宣称全部历史领域类型已替换。未新增网络、数据库或多盘自动写策略。

## 性能与兼容性取舍

严格判断增量“未变”需要核对可信副本和完整内容，成本高于原来的总字节数/文件数/最大 mtime 快跳。当前优先修复漏备，未提供性能提升百分比或真盘吞吐承诺。

旧无阶段事务、无完整 SHA 快照的中断、无所有权的复制残留需要保守处理；这是显式安全兼容性变化。重要资料仍需多副本及定期恢复验证。

锁定 CLI/core 依赖要求至少 Rust 1.85，GUI 的 image 依赖要求至少 1.88。本轮 Windows 实测 Rust/Cargo 1.95.0，不据依赖声明冒称已逐版验证精确 MSRV。

## 发布依赖兼容修复

更新 quick-xml 至0.41.0、webbrowser至1.2.2、wayland-scanner至0.31.11，另修复 anyhow、event-listener和memmap2的兼容安全告警版本。zbus_xml 4.x 无上游兼容修复版，因此以固定来源的最小patch保留其API和GUI可访问性；[来源及修改](../vendor/zbus_xml/PATCH.md)包含官方crate校验和MIT许可证。新增3项合成XML测试覆盖往返、无效类型和写入失败，原有341项加上这3项为344。保留33项安全排除。number_prefix、paste、ttf-parser的停止维护告警仍需后续迁移。

## 验证与剩余边界

Windows 限定安全验收为344通过、0失败、33项安全排除（core/CLI279、GUI62、vendored XML兼容测试3）。32项可能扫描实际卷或读取盘符，1项需要Windows符号链接权限；Linux cfg专属测试不计入这些数字。限定命令见 `scripts/test_safe_windows.py`。fmt、严格workspace Clippy、debug/release构建通过，不能将这些数字与历史版本混用。

GUI修复包括：启动前隔离纯合成Demo；预览绑定启动时配置／选项；全局忙态守卫和取消归属；保留结构化VerifyReport并如实呈现取消、不可验证和仅大小结果；窄窗布局及滚动容器；截图失败非零退出并防止覆盖。

最终debug程序的宽／窄窗口 × 应用缩放100%／125%／150% × 八页共48张自身截图已复看。这不是系统DPI验证。egui指针事件测试不是OS原生鼠标测试；原生焦点请求被拒后停止试验，不绕过限制。原生鼠标／滚动、系统DPI、真实磁盘、断电、外部压缩程序及Linux最终组合未验证。

外部进程仍可在最后一次 hash 后继续改写其已打开的源文件句柄，普通跨平台文件 API 不提供通用内容冻结。该候选检查可检测的身份/内容变化并保留证据，不声称对任意并发写入提供文件系统快照保证。
