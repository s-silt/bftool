# Spec B：Batch 3.5 —— 压缩包专项完整性测试（默认开启）

* 日期：2026-05-28
* 状态：批准（user-approved 2026-05-28）
* 上游：PowerShell 旧版 `-TestArchives` 功能的 Rust 迁移 + 新手友好优化
* 关联 spec：[Spec A：Batch 3](./2026-05-28-batch3-strict-enumeration-design.md)

---

## 1. 一句话

把 PowerShell 旧版的「归档前后用 7-Zip / WinRAR / Bandizip 跑 `t` 测试压缩包内部结构」迁移到 Rust 版，**默认开启**；用户什么都不用配，装了任一压缩工具就自动用。

## 2. 动机

用户场景：**每个项目 = 一个文件夹 + 一个压缩包**。压缩包是单大文件，SHA256 整文件校验能查"字节级损坏"，但**测不出压缩包内部结构是否完整**（比如：源压缩包原本就有损坏、复制中 antivirus 中途加锁、坏盘扇区让某个块字节看起来对但解压报错）。这恰好是用户最关心的"备份完整安全"诉求里 SHA256 兜不住的部分。

PowerShell 旧版有 `-TestArchives` flag 做这事，但默认 OFF —— 新手不知道有这功能就享受不到。新手友好原则：**自动开**。

## 3. 设计决策（已对齐）

| # | 决策 | 选项 |
|---|---|---|
| D1 | 默认 ON / OFF | **默认 ON** |
| D2 | 没装测试器时 | **一次性 warn 提示装 7-Zip + 继续走 SHA256 流程**，不 hard error、不 silent skip |
| D3 | 优先级 | WinRAR（返回码最明确）→ Bandizip → 7-Zip（同 PowerShell 旧版） |
| D4 | 用户关掉怎么写 | `--no-test-archives`，**不**需要双确认（关测试比开 unsafe-no-hash 风险低，SHA256 仍在）。**但与 `--unsafe-no-hash` 互斥**（第四轮 P1 修复）—— 同时关 SHA256 + archive test 只剩 size+count+mtime ≈ 无校验，拒绝运行。配置文件 `test_archives = false` + CLI `--unsafe-no-hash` 也属于这种冲突 |
| D5 | 测试时机 | **dry_run early-return 之后**测源（容量判断也在之后）；SHA256 通过后测目标；任一失败 = 项目失败 |
| D6 | 测试器路径 | 配置文件 `bftool.toml` 三个字段，默认值同 PowerShell 旧版 |
| D7 | 目标失败的回收 | **只对 `archive_failed`** 隔离到 `异常文件/`（user-review-P1 修复）；`tester_errors` / `enum_errors` **不动**目标文件，让用户先修环境 |
| D8 | tester detection | 在 `archive::run` 顶层做**一次**，结果传给 handle_one；没装测试器时也只 warn 一次/run |
| D9 | walkdir 错误 | `test_folder` 收集后让项目失败（与 Spec A 一致，不再 swallow） |
| D10 | 测试器自身异常 | spawn 失败 / 被信号杀 / 无 exit code 一律进 `tester_errors`，**不**进 `archive_failed` —— 避免误隔离好压缩包 |
| D11 | 失败记录格式 | `TestReport::details()` 多行（含路径）给 reporter；`summary()` 单行给 `append_manual`（user-review-P2 修复，之前只有"返回码=N"无路径） |
| D12 | tester_errors 出现后 | **如果 opts.no_hash 是 true**(SHA256 也关了)→ break 整轮停（**第六轮 P1 修复**：否则后续项目落到无校验）。**否则** → 本轮 disable tester，剩下的项目跳过 archive test 但继续 SHA256 流程（第三轮 user-review P2-tester-state 修复）|
| D13 | detect 返回 None + unsafe_no_hash | **bail**（第五轮 P1 修复）。dispatch 阶段只能查"用户显式关 archive test"，没装测试器属于运行时状态，必须在 `archive::run` detect 阶段再加一道。同样的"两个保险都没"的语义 |
| D14 | "fail-closed 一致性" | **逐文件**粒度:只要某文件"SHA256 不在 + archive test 不覆盖它"两个保险同时缺,无论怎么进来 → 一律 bail 或项目失败。覆盖维度:CLI flag 显式关 / 配置文件关 / 没装测试器 / 运行时测试器失效 / 核心 API 直接调用绕过 CLI / 项目里没压缩包 / **项目里有非压缩包文件（第九轮 P2）**。这是用户"备份完整安全"诉求的硬底线 |
| D15 | core-level guard 位置（**第八轮 P1.1**） | `archive::run` 函数顶部第一道 `if opts.no_hash && (!cfg.test_archives \|\| opts.no_test_archives) { bail }`。CLI dispatch 那道（§4.3）保留是为更友好的中文文案,不是唯一拦截 |
| D16 | "unsafe_no_hash 下项目放行条件"（**第九轮 P2 扩展第八轮 P1.2**） | 项目内**每一个**非 cruft 文件必须被压缩包测试覆盖。`TestReport.non_archive_files > 0` 时项目失败(写 `需人工处理.txt`,跳到下一项目,**不破坏整轮**)。只有"全是压缩包"和"完全空项目"两类能在 unsafe_no_hash 下放行。给的错误文案指引"去掉 --unsafe-no-hash 让 SHA256 兜底,或把非压缩包内容先打包" |

## 4. 架构改动

### 4.1 新增 `crates/bftool-core/src/engine/archive_test.rs`

```rust
//! 压缩包内部结构测试：调子进程跑 t 命令验证压缩包没坏。
//! 与 SHA256 字节级校验互补：SHA256 保证"字节没变"，本模块保证"语义结构没坏"。

use anyhow::{Context, Result};
use std::path::{Path, PathBuf};
use std::process::{Command, Stdio};

use crate::reporter::Reporter;

// Copy + Clone 让 archive.rs 解构 `(kind, path)` 元组时 kind 不消耗所有权
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Tester {
    WinRAR,    // 优先：返回码最明确
    Bandizip,
    SevenZip,
}

#[derive(Debug, Clone)]
pub struct TesterPaths {
    pub winrar: PathBuf,
    pub bandizip: PathBuf,
    pub seven_zip: PathBuf,
}

/// 按 D3 顺序探测；找不到返回 None。
pub fn detect(paths: &TesterPaths) -> Option<(Tester, PathBuf)> {
    if paths.winrar.is_file()    { return Some((Tester::WinRAR,   paths.winrar.clone())); }
    if paths.bandizip.is_file()  { return Some((Tester::Bandizip, paths.bandizip.clone())); }
    if paths.seven_zip.is_file() { return Some((Tester::SevenZip, paths.seven_zip.clone())); }
    None
}

/// 文件扩展名是不是可测的压缩包（沿用 PowerShell 旧版列表）
pub fn is_archive(p: &Path) -> bool {
    matches!(
        p.extension().and_then(|s| s.to_str()).map(|s| s.to_ascii_lowercase()).as_deref(),
        Some("zip" | "7z" | "rar" | "001" | "tar" | "gz" | "bz2" | "xz" | "cab" | "zipx")
    )
}

/// 测试结果。
///
/// 三种失败模式严格分开（**user review P1 修复**），让调用方知道该不该隔离目标文件：
/// - `archive_failed`：测试器**确实跑了**，返回了"压缩包坏"的明确返回码。**这些文件应被隔离**重传。
/// - `tester_errors`：测试器自身出问题（spawn 失败、被 AV 拦、exe 不可执行、被信号杀掉等）。**不**应隔离任何目标文件 —— 我们根本没拿到"压缩包坏"的证据。本轮 disable tester，项目失败。
/// - `enum_errors`：walkdir 枚举失败（**P2.2 修复**：不再 swallow）。同样**不**隔离任何目标文件。
#[derive(Debug, Default)]
pub struct TestReport {
    pub ok: bool,
    /// 真实测试返回"损坏"的 archive 路径与原因。仅这些会被隔离重传。
    pub archive_failed: Vec<(PathBuf, String)>,
    /// 测试器执行异常（spawn 失败 / 进程被杀 / OS 错误等）。不代表压缩包坏。
    pub tester_errors: Vec<String>,
    /// walkdir 枚举失败的描述。
    pub enum_errors: Vec<String>,
    /// 实际发现并尝试测试的 archive 数（**第八轮 P1.2 修复**）。
    /// 不区分通过 / 损坏 / 测试器异常 —— 只要 invoke_tester 被调用就 +1。
    pub archives_tested: usize,
    /// 项目里**非 cruft、非压缩包**的文件数（**第九轮 P2 修复**）。
    /// 例如 `main.zip + cover.jpg` 的项目:archives_tested=1, non_archive_files=1。
    /// 这些文件**没被 archive test 测过**,如果 opts.no_hash 同时开,它们就落到
    /// 只有 size+count+mtime,违反 D14 的逐文件 fail-closed。
    pub non_archive_files: usize,
}

impl TestReport {
    /// 给 `reporter.error` 用：多行详细描述（含路径）。
    pub fn details(&self) -> Vec<String> {
        let mut out = Vec::new();
        for (p, reason) in &self.archive_failed {
            out.push(format!("压缩包损坏：{} ({})", p.display(), reason));
        }
        for e in &self.tester_errors {
            out.push(format!("测试器执行异常：{}", e));
        }
        for e in &self.enum_errors {
            out.push(format!("枚举失败：{}", e));
        }
        out
    }

    /// 给 `append_manual` 用：单行摘要（**P2 修复**：之前只有"返回码=2"没有路径）。
    pub fn summary(&self) -> String {
        let parts: Vec<String> = self.details();
        if parts.is_empty() {
            "压缩包测试通过".to_string()
        } else {
            parts.join("; ")
        }
    }
}

/// 单次测试器调用的结果，区分"压缩包坏" / "测试器出问题"。
enum InvokeOutcome {
    Ok,                      // 返回码 0
    NonFatalWarn,            // 返回码 1（WinRAR/7-Zip 的非致命警告）
    ArchiveBad(i32),         // WinRAR/7-Zip >= 2 或 Bandizip != 0：测试器**确认**压缩包坏
    TesterError(String),     // spawn 失败 / 进程被杀 / OS 错误：测试器自己出问题
}

fn invoke_tester(tester: (Tester, &Path), archive: &Path) -> InvokeOutcome {
    let args: Vec<&str> = match tester.0 {
        Tester::WinRAR => vec!["t", "-ibck", "-y", "--"],
        Tester::Bandizip => vec!["t"],
        Tester::SevenZip => vec!["t", "--"],
    };
    let status_res = Command::new(tester.1)
        .args(&args)
        .arg(archive)
        .stdout(Stdio::null())
        .stderr(Stdio::null())
        .status();
    let status = match status_res {
        Ok(s) => s,
        Err(e) => return InvokeOutcome::TesterError(format!(
            "spawn {} 失败 ({}): {}", tester_name(tester.0), tester.1.display(), e
        )),
    };
    let Some(code) = status.code() else {
        return InvokeOutcome::TesterError(format!(
            "{} 进程异常退出（无 exit code，可能被信号杀掉或被 AV 拦截）", tester_name(tester.0)
        ));
    };
    match tester.0 {
        Tester::Bandizip if code == 0 => InvokeOutcome::Ok,
        Tester::Bandizip => InvokeOutcome::ArchiveBad(code),  // Bandizip 非 0 视为压缩包坏
        Tester::WinRAR | Tester::SevenZip if code == 0 => InvokeOutcome::Ok,
        Tester::WinRAR | Tester::SevenZip if code == 1 => InvokeOutcome::NonFatalWarn,
        Tester::WinRAR | Tester::SevenZip => InvokeOutcome::ArchiveBad(code),
    }
}

/// 测试一个文件夹下所有压缩包。
pub fn test_folder(
    folder: &Path,
    tester: (Tester, &Path),
    reporter: &dyn Reporter,
) -> TestReport {
    let mut report = TestReport::default();
    report.ok = true;
    let mut archives: Vec<PathBuf> = Vec::new();

    for entry in crate::engine::cruft::walk(folder) {
        match entry {
            Ok(e) if e.file_type().is_file() => {
                if is_archive(e.path()) {
                    archives.push(e.into_path());
                } else {
                    // 第九轮 P2：枚举到的非 cruft 非压缩包文件 → 计数
                    report.non_archive_files += 1;
                }
            }
            Ok(_) => continue,  // 目录、symlink 等
            Err(err) => {
                report.ok = false;
                report.enum_errors.push(format!("{}", err));
            }
        }
    }

    if archives.is_empty() && report.enum_errors.is_empty() {
        return report;  // ok=true
    }

    reporter.info(&format!(
        "测试 {} 个压缩包（{}）…", archives.len(), tester_name(tester.0)
    ));
    for a in &archives {
        report.archives_tested += 1;  // 第八轮 P1.2：每次 invoke 都计数（无论结果）
        match invoke_tester(tester, a) {
            InvokeOutcome::Ok => {}
            InvokeOutcome::NonFatalWarn => {
                reporter.warn(&format!(
                    "压缩包有警告（{} 返回码=1，非致命）：{}",
                    tester_name(tester.0), a.display()
                ));
            }
            InvokeOutcome::ArchiveBad(code) => {
                report.ok = false;
                report.archive_failed.push((
                    a.clone(),
                    format!("{} 返回码={}", tester_name(tester.0), code),
                ));
                // 继续测下一个：一次看到所有损坏（D4 一致）
            }
            InvokeOutcome::TesterError(reason) => {
                report.ok = false;
                report.tester_errors.push(reason);
                // 一旦测试器自身出问题，剩下的项目本轮也别试了：跳出，让 caller 看到 tester_errors
                break;
            }
        }
    }
    report
}

// run_tester_code 已删除：被上面的 invoke_tester 取代，明确区分
// "测试器跑成功 + 压缩包返回坏" vs "测试器自己出问题"。
// 这是 user review P1 修复的核心 —— 不再把 spawn 失败混进"压缩包坏"语义。

fn tester_name(t: Tester) -> &'static str {
    match t { Tester::WinRAR => "WinRAR", Tester::Bandizip => "Bandizip", Tester::SevenZip => "7-Zip" }
}
```

### 4.3 CLI 加 `--no-test-archives` + Options 加字段 + 冲突检查（**第四轮 P1 修复**）

`crates/bftool-cli/src/cli.rs` 在 `Archive` 子命令下：


`crates/bftool-core/src/engine/archive.rs` 的 `Options` 加字段：

```rust

    pub dry_run: bool,
    pub no_hash: bool,
    pub limit: usize,
    pub drive_letter_override: Option<String>,
    pub no_test_archives: bool,   // 新增
```

**两道防线**（**第九轮 P3.1 修订**）：
- **CLI dispatch（本节,UX 预检）**:在最早的入口拦下,给中文友好文案 + 指出具体 flag 名("`--no-test-archives`"、"`bftool.toml` 的 `test_archives`"等)。**不是**唯一拦截。
- **core `archive::run` 顶部 boolean guard（§4.4,强制边界）**:不管调用方有没有做预检,core 自己也 fail-closed,保证 GUI / 测试 / 第三方调用方都不能绕过 D14。

CLI 这道检查的代码:

```rust
// crates/bftool-cli/src/cli.rs::dispatch 内,Archive 分支
let effective_test_archives = cfg.test_archives && !no_test_archives;
if unsafe_no_hash && !effective_test_archives {
    // CLI flag 关 / 配置文件关 / 两者都关 都进这里
    bail!(
        "拒绝运行：--unsafe-no-hash 与「压缩包测试关闭」不能同时存在。\n\
         同时关掉 SHA256 内容校验和压缩包内部测试 → 只剩文件数 + 大小 + 修改时间，\n\

         如何修：\n\
           - 想保留压缩包测试 → 去掉 --no-test-archives 或 bftool.toml 改 test_archives = true\n\
           - 想用完整 SHA256 → 去掉 --unsafe-no-hash\n\
           - 两个都要关 → 抱歉，工具拒绝这种组合"
    );
}
```

`archive::run` 在做 `tester_opt` 决定之前**先跑 core guard**（§4.4 §第八轮 P1.1 段），然后才用 `if cfg.test_archives && !opts.no_test_archives` 决定 tester_opt。

### 4.4 archive 集成（**P2.1 / P1.2 / P3 一并修复**）

**P3 修复**：tester detection 提到 `archive::run` 顶层，本轮只 detect 一次、只 warn 一次（如果没装）。
**第三轮 P2-tester-state 修复**：tester 是**可变**状态，handle_one 报告 tester_errors 后本轮 disable（避免后续项目重复撞同一个 spawn 错误）。
**第五轮 P1 修复**：detect 返回 None **且** unsafe_no_hash 开时，直接 bail —— 这种"两个保险都不在"的状态 dispatch 静态检查抓不到（用户没显式 `--no-test-archives`），必须在 run 运行时拦下。
**第八轮 P1 修复（core-level guard）**：`archive::run` 是 bftool-core 的**公开入口**，GUI / 测试 / 其它调用方可能直接传 `Options { no_hash: true, no_test_archives: true }` 绕过 CLI 的 dispatch 检查。D14 承诺的"无论怎么进来都 fail-closed"要求 core 自己也加一道独立 guard。CLI 那道（§4.3）保留是为了更友好的中文错误文案,不是唯一拦截。

```rust
// archive::run 顶部第一道 guard —— **core-level**，与 CLI dispatch 互补
if opts.no_hash && (!cfg.test_archives || opts.no_test_archives) {
    anyhow::bail!(
        "拒绝运行：no_hash=true 与 archive test 关闭（配置 test_archives=false 或 opts.no_test_archives=true）\
         不能同时存在 —— 等价于「没在做完整性校验」。这是 core 级 fail-closed 拦截,\
         调用方应该在传 Options 之前就做合并检查（CLI dispatch 已经做了一次更友好的）。"
    );
}

// archive::run 函数顶部（在路径安全检查之后、project 主循环之前）
let mut tester_opt: Option<(Tester, PathBuf)> = if cfg.test_archives && !opts.no_test_archives {
    let p = TesterPaths {
        winrar: cfg.winrar_path.clone(),
        bandizip: cfg.bandizip_path.clone(),
        seven_zip: cfg.seven_zip_path.clone(),
    };
    match archive_test::detect(&p) {
        Some(t) => Some(t),
        None => {
            // 第五轮 P1：detect 失败 + no_hash 同时存在 → 实际上两层校验都没了
            if opts.no_hash {
                anyhow::bail!(
                    "拒绝运行：开启了 --unsafe-no-hash 但**机器上一个压缩包测试器都没装**。\n\
                     此时 SHA256 没在跑，archive test 也跑不起来 —— 只剩\n\
                     文件数+大小+修改时间，等价于「没在做完整性校验」。\n\
                     如何修：\n\
                       - 装一个测试器：推荐 7-Zip（免费开源 https://7-zip.org）；或\n\
                       - 去掉 --unsafe-no-hash，让 SHA256 兜底"
                );
            }
            reporter.warn("未检测到 WinRAR / Bandizip / 7-Zip —— 压缩包内部结构无法测试。\
                          重要资料建议装一个（推荐 7-Zip 免费开源：https://7-zip.org）。\
                          SHA256 整文件校验仍在正常进行。");
            None
        }
    }
} else { None };

// 把 tester_opt 作为可变引用传给 handle_one；handle_one 报告 TesterError 时设 None
for proj in &projects {
    match handle_one(cfg, reporter, &drive, proj, &opts, tester_opt.as_ref()) {
        Ok(HandleOutcome::Done) => handled += 1,
        Ok(HandleOutcome::Skipped) => {}
        Ok(HandleOutcome::TesterFatallyDisabled) => {
            // 第六轮 P1 修复：tester 运行时失效后，如果 opts.no_hash 已开，
            // 后续项目就会落到"无 SHA256 + 无 archive test"的无校验状态 —— 不能继续。
            // 跟 detect 阶段 D13 一致的 fail-closed 语义,只是触发时机不同。
            if opts.no_hash {
                reporter.error(
                    "测试器运行时失效（spawn/被信号杀/exe 被 AV 拦），同时 --unsafe-no-hash 已开 \
                     —— 后续项目将落到「无 SHA256 + 无 archive test」无校验状态。本轮停止。\n\
                     如何修：去掉 --unsafe-no-hash 让 SHA256 兜底，或修复测试器环境后重跑。"
                );
                break;  // 整轮停止,不继续处理后续项目
            }
            // opts.no_hash 是 false:SHA256 还在跑,可以接受 archive test 缺席
            reporter.warn("测试器自身异常 —— 本轮剩下的项目跳过压缩包测试；SHA256 整文件校验仍在。\
                           请检查配置的测试器路径是否正确、exe 是否被 AV 拦截。");
            tester_opt = None;
        }
        Ok(HandleOutcome::DriveSealed) => break,
        Err(e) => { /* 已有处理 */ }
    }
}
```

**`handle_one` 内插入两点**（**P2.1 修复**：源测试**必须**在 `dry_run` early-return 之后）：

> **重要（第六轮 P2 修复）**：以下片段**只展示 archive test 插入位置**。
> dry-run 分支的具体写法以 **Spec A §4.2c 的 `FolderStats` + enum_errors 暴露 warn 版本为准**,
> 实现者不要按本片段简化的 `({:.2}GB)` 单字段版本回退。
> 签名变更（加 `tester_opt`、新返回值）见下；逻辑顺序见下;dry-run 输出格式以 Spec A 为准。

```rust
fn handle_one(
    cfg: &Config,
    reporter: &dyn Reporter,
    drive: &DriveInfo,
    proj_path: &Path,
    opts: &Options,
    tester_opt: Option<&(Tester, PathBuf)>,
) -> Result<HandleOutcome> {
    // ...稳定性检测 + 重名保护 + 容量判断...

    // ===== dry-run early-return =====
    // 写法以 Spec A §4.2c 为准（folder_stats() + "X 个文件 Y GB" + enum_errors warn）
    // 这里只标示位置，不再示意完整代码避免覆盖 Spec A 的设计。
    // {{ Spec A §4.2c dry-run 分支 }}

    // P2.1：dry_run check 之后才调用 tester（测源压缩包）
    // 源失败语义：永远**不**隔离源文件（源在 SSD，不能动）
    if let Some((kind, path)) = tester_opt {
        let r = archive_test::test_folder(proj_path, (*kind, path), reporter);
        if !r.ok {
            for line in r.details() { reporter.error(&line); }  // P2 修复：含路径的多行详细
            append_manual(cfg, &name, &format!("源压缩包测试失败：{}", r.summary()))?;
            // 第三轮 P2-tester-state：tester_errors 触发时返回新 outcome 让 run 本轮 disable tester
            if !r.tester_errors.is_empty() {
                return Ok(HandleOutcome::TesterFatallyDisabled);
            }
            return Ok(HandleOutcome::Skipped);
        }

        // 第九轮 P2 修复（扩展第八轮 P1.2）：opts.no_hash 下逐文件 fail-closed
        //   archive_test 只能保护**压缩包**,SHA256 不在时,任何**非压缩包文件**
        //   (.jpg / .mp4 / .pdf / .doc ...) 落到只有 size+count+mtime,违反 D14。
        //   触发条件:opts.no_hash && 项目里有任何非 cruft 非压缩包文件。
        //   覆盖三种情况:
        //     - 完全空项目(0 文件): non_archive_files == 0 → 允许(不破 D14)
        //     - 全是非压缩包文件: non_archive_files > 0 → 拦下
        //     - 混合(压缩包 + 非压缩包): non_archive_files > 0 → 拦下
        //   只有"全是压缩包"和"完全空"两类项目能在 unsafe_no_hash 下放行。
        if opts.no_hash && r.non_archive_files > 0 {
            reporter.error(&format!(
                "本项目有 {} 个非压缩包文件,开启了 --unsafe-no-hash —— 这些文件没有 SHA256, \
                 也不能被 archive test 覆盖,只剩 size+count+mtime,违反完整性校验底线。",
                r.non_archive_files
            ));
            append_manual(cfg, &name, &format!(
                "unsafe_no_hash 模式下项目有 {} 个非压缩包文件 → 这些文件无完整性校验。\
                 请去掉 --unsafe-no-hash 让 SHA256 兜底,或把非压缩包内容打包成一个压缩包后再归档。",
                r.non_archive_files
            ))?;
            return Ok(HandleOutcome::Skipped);  // 项目级失败,后续项目继续
        }
    }

    // ...生成源清单 + 复制 + SHA256 校验...

    // 目标测试。P1 修复：只有 archive_failed 才隔离；tester_errors/enum_errors 不动目标文件
    if let Some((kind, path)) = tester_opt {
        let r = archive_test::test_folder(&dest, (*kind, path), reporter);
        if !r.ok {
            for line in r.details() { reporter.error(&line); }

            // 只隔离"测试器确认压缩包坏"的文件；不动 tester_errors / enum_errors 涉及的好文件
            if !r.archive_failed.is_empty() {
                let quar = paths::drive_quarantine_dir(&drive.root).join(&name);
                let mut moved = 0usize;
                for (bad, _reason) in &r.archive_failed {
                    if let Ok(rel) = bad.strip_prefix(&dest) {
                        let to = quar.join(rel);
                        if let Some(p) = to.parent() { fs::create_dir_all(p).ok(); }
                        if let Err(e) = fs::rename(bad, &to) {
                            reporter.warn(&format!("隔离失败 {}：{}", bad.display(), e));
                        } else {
                            moved += 1;
                        }
                    }
                }
                reporter.action(&format!(
                    "已隔离 {} 个损坏压缩包到 {}；下次运行会自动补传并重测。",
                    moved, quar.display()
                ));
            }

            // tester_errors / enum_errors 出现时，目标文件保持不动（不隔离）。
            // 这意味着下次重跑时 copy_folder 看到目标都还在、size 一致，会跳过文件复制 ——
            // 但 tester_errors 通常源于环境问题（exe 没了、被 AV 拦），下次重跑前用户
            // 应该已经修复环境；如果没修，下次仍然 tester_errors，项目继续失败，
            // 直到环境修好。这是预期行为：宁可慢、宁可让用户修，也不要瞎删好文件。

            append_manual(cfg, &name, &format!("目标压缩包测试失败：{}", r.summary()))?;
            // 第三轮 P2-tester-state：tester_errors 触发时让 run 本轮 disable
            if !r.tester_errors.is_empty() {
                return Ok(HandleOutcome::TesterFatallyDisabled);
            }
            return Ok(HandleOutcome::Skipped);  // 不移动源、不写索引
        }
    }

    // ...复核源 + 事务式提交...
}
```

源失败 / 目标失败两种语义不同：
- 源压缩包坏 → **不复制**，不需要隔离（源不变），写人工处理
- 目标压缩包坏 → **隔离失败文件**（移到 异常文件/），下次 `copy_folder` 发现目标缺这些文件会自动补传 → 然后重新校验 + 重新测试

> P1.2 隔离机制的细节：`copy_folder` 当前按 size match 跳过已存在文件（archive.rs:585）。一旦坏文件被 `rename` 到隔离目录，下次跑时 dst 上就**没有**这个文件，`copy_folder` 就会从源**重新复制**过来。然后 SHA256 + archive_test 都会重测。这正是路线图描述的"打破死循环"。

## 5. 错误处理与用户提示

| 场景 | 行为 |
|---|---|
| 用户没装任何压缩工具 + 默认 ON + 没开 unsafe-no-hash | 第一次跑 archive 时一条 warn 提示装 7-Zip + 继续 SHA256 流程；后续运行重复提示（一次/run） |
| 用户没装任何压缩工具 + 同时开 --unsafe-no-hash | **拒绝运行**（D13/D14 fail-closed）—— 两个保险都没,不能继续 |
| 用户装了 7-Zip | 自动用，无提示无配置 |
| 用户装了 WinRAR + 7-Zip | 用 WinRAR（D3 优先级） |
| 源压缩包本身就坏 | 在"复制"开始前就发现，节省机械盘 IO，项目失败 + 人工处理 |
| 复制后目标盘上压缩包坏 | 校验通过 + 测试失败 = 项目失败，不移动源、不写索引，下次会自动重传（已有的隔离重传机制） |
| 用户传 `--no-test-archives` | 不调用 detect / test，直接跳过；CLI 不报 warn，因为用户明确选了"不测" |

## 6. 测试边界

1. `archive_test::is_archive`：覆盖所有 10 种扩展名（大小写、含路径）
2. `archive_test::detect`：四种组合（都没装 / 只有 7z / 只有 winrar / 三个都有）→ 返回值
3. `archive_test::test_folder`（返回 `TestReport`，**P1.2 + P2.2 + user-review-P1 + 第八轮 P1.2 + 第九轮 P2 修复**）：
   - 空文件夹 → `ok==true`, archive_failed/tester_errors/enum_errors 都空, **`archives_tested==0`, `non_archive_files==0`**
   - 文件夹里只有 .mp4 .jpg .pdf 没压缩包 → `archives_tested==0`, **`non_archive_files==3`**
   - 一个合法 .zip → ok==true, **`archives_tested==1`, `non_archive_files==0`**
   - 一个 .zip + 一个 .jpg → ok==true, **`archives_tested==1`, `non_archive_files==1`**（第九轮 P2 新增混合 case）
   - 两个损坏 .zip → ok==false, **archive_failed.len()==2**, **`archives_tested==2`**, `non_archive_files==0`
   - WinRAR exit 1 → reporter.warn + ok==true（NonFatalWarn）
   - Bandizip exit 0 → ok==true；Bandizip exit 非 0 → archive_failed.push
   - 含一个不可读子目录 → ok==false, **enum_errors 非空，archive_failed 空**（不再 swallow,但不误隔离）
   - **子进程 spawn 失败**（单元测试可绕过 `detect` 直接给 `test_folder` 传不可执行的路径：不存在的文件 / 权限拒绝 / 0 字节文件等）→ ok==false, **tester_errors 非空, archive_failed 空**（user-review-P1 修复:不再混进 archive_failed 害得调用方误隔离好文件）
   - **子进程被信号杀**(status.code() 是 None)→ ok==false, tester_errors 非空, archive_failed 空
   - tester_errors 触发后立即 break（不再尝试剩下的 archive；调用方据 tester_errors 处理）
4. `TestReport::summary()` 和 `TestReport::details()`：
   - 三种失败模式都被纳入 summary/details
   - details() 每条都含路径或具体原因（**user-review P2 修复**：不再只是 "返回码=2"）
4. **P2.1 集成测试**：`bftool archive --dry-run` 触发 archive::run，但 handle_one 在 dry_run 早 return，**断言 `archive_test::test_folder` 没被调用**（mock 一个会 panic 的 tester 验证）
5. 集成：`bftool archive --no-test-archives` 时三个测试器路径都存在，tester_opt = None，不调用 detect / test
6. **P3 集成测试**：跑 3 个项目 + 配置三个测试器路径都不存在 → 验证 "未检测到 ..." warn 只出现 **1 次**（detection 在 run 顶层，不是每项目）
7. **P1.2 集成测试**：故意把目标盘上某个 .zip 用 truncate 写 0 字节模拟损坏 → 跑 archive → 验证：(a) 项目失败 (b) 该 .zip 被移到 异常文件/ (c) 第二轮 archive 该 zip 被重新复制 + 重新测过
8. **user-review-P1 集成测试（第七轮 P3 修正）**：配 7-Zip 路径指向一个**存在但不是有效 exe 的文件**（例如 `tempdir/fake7z.exe` 写 0 字节,detect 通过 `is_file()` 但 invoke_tester 时 `Command::new(...).status()` 失败）→ 跑 archive → 验证：(a) 项目失败 (b) 目标盘 .zip **保留原状,没被移走**（archive_failed 为空，tester_errors 非空 → run 知道只动 archive_failed）(c) reporter 输出 tester_errors 详情 (d) 需人工处理.txt 包含 spawn 失败原因
9. **user-review-P2 集成测试**：tester_errors 触发后，`append_manual` 写入的行**包含**具体路径或失败原因，不是空字符串或纯"返回码=N"
10. **第三轮 P2-tester-state 集成测试（第七轮 P3 修正）**：3 个项目 + 7-Zip 路径指向**存在但不可执行**的文件 → 跑 archive → 验证：(a) 第 1 个项目失败 `TesterFatallyDisabled` (b) run 输出 "本轮剩下的项目跳过压缩包测试" warn (c) **第 2、3 个项目继续走 SHA256 流程**（不再尝试 archive test），不重复"测试器异常"的错误 (d) `需人工处理.txt` 只有 1 行 tester_errors（不是 3 行重复）
11. **第四轮 P1 集成测试**：dispatch 阶段的冲突检查（**第五轮 P3-flag-name 修复**：用正确的 `--i-understand-this-can-miss-bitrot` 全名）
    - (a) `--unsafe-no-hash --i-understand-this-can-miss-bitrot --no-test-archives` 三个一起 → bail 友好错误
    - (b) `--unsafe-no-hash --i-understand-this-can-miss-bitrot` + `bftool.toml` 里 `test_archives = false` → bail
    - (c) 只传 `--no-test-archives`（不传 unsafe-no-hash）→ 正常运行
    - (d) 只传 `--unsafe-no-hash --i-understand-this-can-miss-bitrot`（不传 no-test-archives，配置 test_archives=true）→ 正常运行
12. **第五轮 P1 集成测试**：archive::run 顶层 detect None + unsafe_no_hash 的运行时检查
    - (a) 三个测试器路径都指向不存在的 exe + `--unsafe-no-hash --i-understand-this-can-miss-bitrot` → archive::run 内 detect 返回 None → **bail**（不是 warn+continue）
    - (b) 同上但**没**传 unsafe-no-hash → 正常 warn+continue（SHA256 兜底）
    - (c) 装了 7-Zip + `--unsafe-no-hash --i-understand-this-can-miss-bitrot` → 正常运行（archive test 接管）
13a. **第八轮 P1.1 集成测试**：`archive::run` core-level guard 不靠 CLI dispatch
    - (a) **绕过 CLI 直接调用** `engine::archive::run(&cfg, reporter, Options { no_hash: true, no_test_archives: true, .. })` → core 自己 bail（不依赖 CLI 检查）
    - (b) `cfg.test_archives = false` 配置 + `Options { no_hash: true, no_test_archives: false }` → core bail（配置层也覆盖）
    - (c) `Options { no_hash: false, no_test_archives: true }` → 正常运行（SHA256 兜底）
13b. **第八轮 P1.2 + 第九轮 P2 集成测试**：unsafe_no_hash 下逐文件 fail-closed
    - (a) 装了 7-Zip + 项目里只有 `.mp4 .jpg .pdf`（没任何压缩包扩展名）+ `--unsafe-no-hash --i-understand-this-can-miss-bitrot` → `r.non_archive_files == 3` → 项目 `Skipped` + 写人工处理.txt + reporter.error 指出"有 3 个非压缩包文件无完整性校验"
    - (b) 同上但**没**传 unsafe-no-hash → 正常运行（SHA256 走完整哈希,任何文件类型都不是问题）
    - (c) 同 (a) 但**多个项目**,其中 1 个全是 .zip,1 个全非压缩包,1 个混合 → 全 .zip 的成功,后两个失败到人工处理(整轮**不** break)
    - (d) **第九轮 P2 关键 case**:项目里有 `main.zip + cover.jpg` + unsafe_no_hash → `archives_tested == 1`, `non_archive_files == 1` → 项目失败（不是因为 archives_tested==0,而是因为 non_archive_files>0)
    - (e) **完全空项目** + unsafe_no_hash → non_archive_files == 0 → 放行（D16 允许:空项目不破 D14)
14. **第六轮 P1 集成测试（第七轮 P3 修正）**：tester 运行时失效 + unsafe_no_hash 的状态机
    - **触发"运行时失效"的方法**：detect 成功（路径指向一个**存在但不可执行**的文件，例如 0 字节 `fake7z.exe`），是 `is_file()==true` 让 detect 通过，然后 `invoke_tester` 时 `Command::new(...).status()` 返回 `Err` → `InvokeOutcome::TesterError` → `tester_errors` 非空。
    - 路径指向一个不存在的文件不行 —— 那会被 detect 在 `is_file()` 阶段过滤掉变成 detect None,走 case 12 而不是这条。
    - (a) 3 个项目 + 7-Zip 路径指向不可执行的 0 字节文件 + `--unsafe-no-hash --i-understand-this-can-miss-bitrot` → 第 1 个项目失败 + run **break 整轮**（不继续第 2/3 个）+ reporter 输出"无 SHA256 + 无 archive test"错误
    - (b) 同上但**没**传 unsafe-no-hash → run 继续第 2/3 个项目（SHA256 兜底）,与第三轮 P2-tester-state case 10 行为一致

## 7. 不做的事

- 不做 `--force-test-archives`（强制要求装测试器，没装就 fail）—— 跟 D2 哲学冲突
- 不做"测试器路径自动探测"（注册表搜索 / `where` 命令）—— 新手默认路径够，进阶用户改 toml
- 不做压缩包结构修复（PowerShell 旧版也没有）—— 损坏的压缩包就让用户处理
- 不做并行测试（同一项目通常 1 个压缩包，并行没收益）

- 默认 ON 意味着升级后**会**多走一遍压缩包测试，可能让原本 OK 的项目耗时增加：
  - 这是 user 明确想要的（「新手优化但备份完整安全」）
  - 不想要的用户：`bftool archive --no-test-archives` 或 `bftool.toml` 里 `test_archives = false`

## 10. 一句话给新手

> 装了 7-Zip（免费开源）后，bftool 会在归档前后各测一次压缩包内部结构，确保字节没变、结构也没坏。**默认走 SHA256** 时没装也能跑，只是少一道压缩包专项保险,SHA256 整文件校验照常。**若同时开了 `--unsafe-no-hash`,则按 D13/D14 拒绝运行**(两个保险都没,工具不允许)。
